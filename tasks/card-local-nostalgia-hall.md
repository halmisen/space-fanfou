# 长任务卡：本地饭否怀旧馆

状态：active
建卡：2026-08-13
来源：用户授权独立研发；用户报告个人归档的大号真实 Windows Chrome 验收已完成。

## 1. 问题

现有归档首先解决了「自己的消息不丢」，但它还不是能回看完整个人历史的地方：收到的提及、收藏和
私信没有统一呈现。目标是生成一个只在用户磁盘运行、可断网浏览的个人饭否怀旧馆；它不替代饭否，
不提供发布、回复、关注或服务器。

## 2. 冻结标准

### 第一切片：收到的提及

1. 复用现有 OAuth 通道，以严格串行分页把 `statuses/mentions.json` 落到 `mentions/`；按 ID 去重，
   有独立水位、页数、计数与可见范围说明。
2. 原归档数据不迁移、不重写；旧版 `meta.json` 可继续读，首次同步后只增加字段。
3. 离线总览显示「消息」和「提及」两个入口，提及页复用相同的 XSS 转义、CSP、离线资源策略。
4. 单元测试覆盖分页到底、重复 ID、失败水位保留、旧 meta 兼容、生成页不执行恶意正文。
5. `npm test`、`npm run build` 和 `git diff --check` 均通过。

### 私信直接备份

1. 用户于 2026-08-13 明确授权将私信直接保存到所选本地目录。同步使用 OAuth 1.0a 的只读
   `conversation_list` 与逐会话读取；不得发送、删除或改变饭否数据。
2. 每个会话独立落盘，按消息 ID 去重；每页先落盘再推进恢复位置。面板显示条数和会话数，不显示正文。
3. 同步前必须明确提示：静态私信文件没有访问控制，用户应选择只有自己可访问的文件夹。接口检查仅作
   无写入诊断，不能以未取得检查收据阻止已授权的备份。

### 当前实施状态

- 收到的提及已在提交 `afa709c` 中完成代码、测试和构建验证；真实 Windows Chrome 的提及验收尚待本轮扩展重载后执行。
- 私信探针已实现为显式确认的只读操作：只读取对话列表首页和一个受控会话，收据只留在设置页内存中。
  它保留为接口诊断；私信正式备份已获用户授权，真实 OAuth 和目录落盘验收仍待执行。

## 3. 已冻结的设计

数据目录按流拆分：`statuses/YYYY-MM.json`、`mentions/YYYY-MM.json`、`favorites/favorites.json` 和
未来的 `direct-messages/<conversation>.json`。每条记录保留原 API 对象和 `_archive.archiveSource`；
`meta.json` 为每一流保存计数、水位、完成度与最后错误。离线 HTML 是静态阅读器：总览、消息、提及、
收藏和私信为独立入口，所有内容均先转义，CSP 禁止网络。

私信默认关闭，并与普通归档分开确认。静态文件没有访问控制；若用户要求防止文件被复制，必须单立
本地加密和密钥恢复设计，不能把普通 HTML 当作加密。

## 4. 边界

- 不创建服务器、账号体系、分享链接或在线饭否替代品。
- 不发送、删除、回复、转发、收藏或修改任何饭否数据。
- 不把目录句柄、OAuth、Cookie、私信正文、账号 ID、验收截图或探针原始响应写入 Git。
- 不修改 `origin/simplify`，不改变现有归档目录中已经提交的数据。

## 5. 实施顺序与恢复指针

1. 实现并测试逐会话私信备份、恢复位置和离线阅读；接口检查可用于诊断，不是准入门。
2. 在真实桌面 Chrome 验收私信 OAuth 返回、文件落盘和离线页面；失败则记录安全错误，不影响既有消息与提及。
3. 实现收藏流及其完整扫描语义。

`src/features/personal-archive/{fanfouClient,sync,fsStore,buildHtml}.js`。关闭条件是消息、提及、私信与
收藏均有代码、测试、构建和真实桌面 Chrome 的无敏感验收收据。
