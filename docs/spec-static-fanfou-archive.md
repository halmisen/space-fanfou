# Spec: 太空饭否怀旧版首页

状态：讨论稿，尚未授权实现

## Problem Statement

现有个人归档能保存消息、提及、收藏、私信和媒体，但把“生成归档网站”做成了独立目的。用户需要先离开饭否首页，理解数据流和年份，再进入一套档案页面；这不符合“想回去看看过去饭否”的自然动作。

目标是在**现有太空饭否首页皮肤**上增加怀旧能力，不复制另一个产品，也不保存所有饭否用户。用户默认仍看实时饭否首页；当他从右侧栏选择年份、人物、今天的往年或年度回顾时，主时间线在同一套皮肤内切换到本地历史快照。每次用户主动同步才更新历史数据。

## Solution

### 1. 产品原则

1. 首页是产品中心，备份是它的数据底座。用户选择内容范围后，点击一个主按钮完成同步和媒体补全；单项重试放到高级操作，不把“生成网站”放成首页主任务。

2. 默认态完全保留当前太空饭否首页：实时首页时间线、发言和现有皮肤都不被历史功能替代。怀旧态也沿用同一套消息卡片、头像、转发、图片和时间线布局，只在顶部显示“历史快照”、数据截至时间和“返回现在”。

3. 右侧栏在现有信息区下方增加“穿越时间”：默认展示可用年份和每年消息数，并提供“全部历史”“今天的往年”和“年度回顾”。年份是导航，不是新的默认首页；点击后在主区域显示选中年份的本地时间线。

4. 怀旧态只呈现已经归档的内容：我的消息、收到的提及、收藏和私信是四条可切换的本地流，而不是伪造一条历史关注首页。年度十大关键词、最活跃时段和互动排行是侧栏入口；点击后仍可跳回同皮肤的原帖筛选结果。

5. 离线静态导出保留为备份的可选产物：它复用“怀旧态”皮肤，打开后默认展示最近一次归档的消息流和同一侧栏，不承担在线首页的角色，也不自动刷新。

### 2. 用户流程

```text
日常打开饭否首页
  → 默认浏览实时首页
  → 右侧栏选择“穿越时间”或“年度回顾”
  → 主时间线切换为本地历史快照
  → 随时点“返回现在”回到实时首页

主动备份时：选择备份范围 → 同步原始消息并保留各流断点 → 汇总头像与图片 → 更新本地索引、侧栏和可选离线导出。
```

备份范围默认包含“我的消息”和离线阅读所需的媒体。用户可添加提及、收藏和私信；私信需要单独确认，因为可选静态导出没有访问控制。媒体下载失败不阻止文本归档完成，但首页怀旧态和离线导出都必须显示缺失数和重试入口。

### 3. 首页与侧边栏的信息结构

1. **默认首页**：保持实时饭否首页；历史索引未准备好时，右侧栏只显示“开始备份以开启穿越时间”，不影响任何现有首页功能。

2. **右侧栏的穿越时间**：先显示“全部历史”和“今天的往年”，再按年份列出有记录的年份和自己的消息数；选中项清晰高亮。年份列表来自轻量索引，不读取整年消息。

3. **怀旧时间线**：我的消息、收到的提及、收藏、私信各自独立。默认按时间倒序；支持年份、月份、小时段、人物、关键词、有图和互动类型（回复、转发、@）筛选。人物索引包含消息作者、转发作者、回复对象、@ 对象和私信对方；@ 对象没有用户 ID 时，以规范化的 @ 名称作为本地人物标识。所有日期筛选使用 `meta.archiveTimezone`。历史量大时按年分卷，不把数万条消息塞进一个 HTML 文件。

4. **年度回顾**：从侧栏打开，按自然年浏览；它是可探索的数据页，不做适合分享而牺牲口径的单张“年报海报”。

## User Stories

1. 作为太空饭否用户，我想默认仍看到实时首页，并能从右侧栏回到旧消息，所以我不必在“现在”和“过去”之间切换产品。

2. 作为归档用户，我想可选地在没有网络时打开同样的怀旧界面，所以消息、头像、图片、样式和筛选脚本都在备份文件夹内。

3. 作为归档用户，我想只点一次“开始/继续备份”，所以系统按固定顺序完成已选数据流、媒体、首页侧栏索引和可选离线导出，并能从中断处恢复。

4. 作为归档用户，我想看到未关注但和我发生过关系的人，所以提及、收藏、转发和私信中出现的人也有本地头像。

5. 作为归档用户，我想知道每一年和谁聊得最多、自己最常说什么、何时最活跃，所以回顾页可从同一份归档给出可追溯的统计。

6. 作为太空饭否用户，我想点“今天的往年”看到历年同月同日的旧消息，所以怀旧不只是一张年份目录。

## Implementation Decisions

### 1. 数据与页面的关系

原始归档是唯一事实来源：消息、提及、收藏和私信继续各自保存原始 API 对象与同步水位。首页怀旧索引、媒体索引、年度统计和可选静态 HTML 都是可删除、可从原始归档重建的派生物。首页不能直接取得设置页授权的目录句柄，因此“首页怀旧索引”保存在扩展源的本地 IndexedDB：同步每次成功落盘后按月写入；已有归档由设置页逐月重建。它不使用 `chrome.storage` 保存消息正文，也不保存私信。

生成必须分成两个模块，而不是把完整归档和全部 HTML 同时放进内存。

1. 索引模块的 seam（模块对外接口）是：`按资源分片读取归档 + meta -> 分卷索引、分卷媒体目标、统计汇总和覆盖范围`。它一次只消费一个分片；自己的消息、提及、收藏和私信分别按年或会话写入可重建的分卷索引及媒体目标。人物头像按用户 ID 写入磁盘键值索引，避免无界内存 Map。

2. 首页怀旧模块的 seam 是：`resolveNostalgiaView(route, IndexedDB 的目标年分卷, 本卷可用媒体索引) -> 时间线视图模型`。`route` 只能是“全部历史、某年、今天的往年、年度回顾或四条流中的一种”；调用方用现有太空饭否消息卡片渲染该模型，并可通过“返回现在”恢复实时首页。饭否页通过扩展消息桥只请求目标年，background 从扩展源 IndexedDB 返回视图数据；该模块不得读取完整原始归档、请求饭否或修改归档数据。

3. 离线导出是同一视图模型的第二个调用方：`renderVolume(时间线视图模型) -> 一个 HTML 文件`。调用方逐卷写入并释放结果；离线导出不能决定在线首页的默认态。

媒体收集器按卷读取索引模块的媒体目标，因此能覆盖所有已选流，而不是只扫描自己的消息流。任何派生产物要么按卷或哈希分区落盘，要么必须证明其规模只随固定名次或不同用户数增长，不得无界地随消息条数常驻内存。首页和每一卷都使用相对链接；小型归档可以只有一卷，但不能假定所有归档、索引或 HTML 结果都能装进一个对象。

### 2. 首页状态与备份执行

首页只有两种互斥状态：`live`（默认，现有实时首页）和 `nostalgia`（用户主动从右侧栏进入的本地历史）。切换到 `nostalgia` 时保留同一页面皮肤与侧栏，顶部提供数据截至时间和“返回现在”；刷新或点击返回现在后恢复 `live`，不能静默把用户留在旧消息中。

“今天的往年”使用 `meta.archiveTimezone` 的月日，从自己的消息中匹配所有年份；没有匹配时显示空态，不用相邻日期凑数。

主界面显示一个备份计划，而不是六个并列按钮：

| 层级 | 用户选择 | 系统行为 |
| --- | --- | --- |
| 内容 | 消息、提及、收藏、私信 | 各流串行同步，独立水位和断点 |
| 阅读材料 | 头像与图片 | 从所有已选流汇总并去重下载 |
| 产物 | 首页侧栏索引、年度回顾、可选离线导出 | 从磁盘原始数据生成，不再联网 |

系统同一时刻只运行一个写盘任务。重新执行计划时，只同步有新数据或未完成的流；照片按同一来源文件是否已存在跳过。头像另有来源 URL 记录：同一用户的观察 URL 改变时，必须重新下载并更新该用户的当前头像引用，不能被“文件已存在”误判为无需更新。所有页面可逐卷重建，避免新数据和旧索引不一致。

### 3. 头像与图片

头像的范围是“归档中出现的人”，不是“我未关注的所有人”。普通状态和转发状态使用其中的 `user.id` 与 `profile_image_url`；私信头像先以现有的只读私信探针取得一份实际接口回执，只有该回执确认没有头像 URL 时，才可以请求 `users/show`。

头像按用户 ID 存储，下载时记录来源 URL、观察时间、文件路径和失败原因。若同一用户在归档中出现多个头像 URL，选择按消息时间最新的一项，不能依赖遍历顺序偶然决定。这是本次归档读取到的当前头像快照，不声称还原历史每一刻的头像。未知图床域名必须按域名显示为“未下载”，不得静默忽略。

### 4. 年度回顾的统计口径

所有回顾默认按自然年、以用户自己的消息为基础；每一项显示样本量和范围。

| 页面指标 | 计算口径 | 不应混入 |
| --- | --- | --- |
| 发帖最多的年、月、日、小时段 | 自己消息按 `meta.archiveTimezone` 的发表时间分桶 | 提及、收藏、私信 |
| 十大关键词 | 自己消息正文；中文 n-gram 与英文词切分，停用词、链接、@用户名和转发标记剔除 | 未经确认的私信正文 |
| 十大公开互动对象 | 自己消息中的回复、转发、@信号分别计数，并显示构成；缺少原转发对象的记录不计入该项 | 把它称为“聊天” |
| 十大聊天对象 | 已选私信中双方消息按会话对象计数；发送和收到分列，并显示总数 | 没有私信数据时的推测 |
| 谁最常 @ 我 | 提及流按作者计数 | 公开互动或私信 |

“聊天最多”只在用户已备份私信且同意把私信用于本地统计时显示。否则页面应显示“未纳入私信，不能判断聊天最多的人”，而不是以公开 @ 或回复偷换概念。

关键词统计先将词频按哈希分区落盘并逐分区聚合，只保留全局前十；再第二次扫描收集这十个词的原帖列表，不能为全部 n-gram 常驻倒排索引。关键词页面须允许查看贡献该词的原帖列表。互动榜跳转必须带本地人物标识与互动类型（回复、转发或 @）；活跃时段跳转必须带小时段；两者都使用 `meta.archiveTimezone` 的本地时间线筛选结果。日期统计不得跟随生成机器或浏览器的本地时区；当前归档默认写入 `Asia/Shanghai`。这样统计是入口，不是无法核查的结论。

### 5. 隐私、完整性与兼容

1. 可选静态导出保持离线 CSP，打开页面时不得有网络请求；OAuth、Cookie、请求签名和目录句柄不得写入备份文件。在线首页怀旧态只读取本地归档，不为查看旧消息额外请求饭否。

2. 私信正文、会话对象和私信统计只留在用户选择的文件夹；不得写进扩展同步存储、日志或截图。

3. 每次首页怀旧索引或离线导出生成时，元数据记录源流完成状态、数据截至时间、媒体成功/失败数和统计范围。对中断、失败或未回溯完成的资源，还要记录停止原因和已知覆盖时间范围。未完成的提及、收藏或私信必须在对应页面明确标记“部分归档”；受影响年度的统计必须标成“仅按已覆盖窗口计算”，或直接隐藏该指标。没有记录的月份不能被推断为没有发帖。

4. 旧备份目录必须仍能阅读。新增媒体索引和统计文件时采用新 schema 字段及可重建派生文件，不能重写或丢弃已有原始分片。

## Testing Decisions

1. 对索引模块和 `resolveNostalgiaView` 使用固定 fixture：四条流、转发、非关注用户、头像 URL 变化、缺图和恶意正文。验证年份、今天的往年和四条流都只读取目标卷；媒体按卷读取；关键词按分区聚合后仅为前十收集原帖。离线 `renderVolume` 验证逐卷写入时不汇集完整文件表、只引用已落盘媒体、所有文本转义且没有外部 URL。

2. 对媒体收集器验证：提及、收藏、转发作者和私信发件人均进入头像清单；同一用户去重；最新观察头像胜出且 URL 改变后更新本地引用；未知域名可见；单张失败不阻断其余下载。

3. 对统计聚合使用纯函数用例：`meta.archiveTimezone` 下的自然年边界、并列第一的稳定排序、停用词、公开互动与私信聊天不混算，以及私信未选择时不展示聊天榜。验证回复、转发与 @ 的榜单跳转均能以人物和互动类型复现对应原帖。另用中断资源夹具断言受影响统计会显示覆盖窗口或被隐藏。

4. 集成验收：以真实桌面 Chrome 打开首页，确认默认实时时间线和现有功能不变；从右侧栏进入某年、今天的往年与年度回顾，确认主区域换成历史时间线且“返回现在”恢复实时首页。完成一次可中断的同步后，在受影响年度回顾确认覆盖窗口提示或指标隐藏与数据截至时间一致。断网后打开可选离线导出的首页、四条流和任一年度回顾页，Network 为零请求。验收只记录无敏感结果。

5. 实现完成门槛：相关单元测试、`npm test`、`npm run build` 与 `git diff --check` 通过；真实 Chrome 验收确认默认首页未被替换、侧栏年份穿越、返回现在、数据截至、缺失媒体提示和统计跳转均可见。

## Out of Scope

- 不重写饭否的实时首页、关注推荐、发布、回复、收藏或私信发送能力；只在现有首页上叠加本地怀旧入口与历史时间线状态。
- 不抓取和归档未发生关系的陌生用户资料。
- 不上传、分享或建立服务器端账号。
- 不把统计结果包装成无法查看原始消息来源的算法结论。

## Further Notes

1. “按照饭否逻辑”在这里指阅读模型相同，不是数据范围相同。即使未来确认有 `home_timeline`，也不能把当前首页当作过去任意时刻的首页：当前关注关系可能已变化，服务端的历史回溯深度也未知。

2. 既有设计已确认：年度报告应读取本地归档，而不是另起一套同步；本规格把它从独立报告页改为首页右侧栏可进入的年度回顾。

3. 私信 API 是否稳定返回发送者头像 URL 尚未确认；实现前必须让现有的无写入探针留下实际接口回执，再决定是否添加按需资料查询。

4. 转发对象排行依赖原始记录中的转发对象字段；实现前用真实已归档样本确认字段覆盖率。字段缺失时，页面必须显示该排行未计入缺失对象，而不是猜测作者。

5. 视觉设计应复用当前太空饭否首页皮肤和饭否时间线可读性；右侧栏只在现有信息区下方增加“穿越时间”和“年度回顾”，不能把首页做成大屏海报或仪表盘。
