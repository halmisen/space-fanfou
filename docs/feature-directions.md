# 太空饭否：可以往哪儿走

Updated: 2026-07-30
Executor: claude
Status: 供阅读与选择，不含任何已排期承诺

这份文档把「我们能做什么」摊开摆平，一个方向一小节，写给你一个人读。
每个方向都写清四件事：**它对用户是什么**、**这想法从哪来的**、**我们离它有多远**、**代价是什么**。

不需要你懂代码。看完选几个想做的告诉我就行。

工作量都是粗估：带「spec 已定稿」的来自对应设计文档里的估算，其余是我按同类功能的经验估的，会有出入。

---

## 零、先说清楚我们已经有什么

免得你在下面看到某个方向时想「这个不是早就有了吗」。目前插件里能用的功能：

| 分类 | 已有的 |
| --- | --- |
| 时间线 | 展开回复/转发上下文、消息内容增强、自动加载更多、新消息处理、**静音饭友** |
| 侧栏 | 有爱饭友、关注话题的新消息提醒、**统一三个饭友面板的显示方式** |
| 批量管理 | 批量删消息、批量删私信、批量管理关注 |
| 外观 | 半透明侧栏、阴影、关闭他人自定义模板、**饭否字体预设**、**关注者头像壁纸** |
| 输入 | 浮动输入框、剪贴板粘贴图片、@ 自动补全 |
| 工具 | 桌面通知、右键分享到饭否、好友关系检查、**OAuth 一键授权** |
| 玩的 | 头像壁纸消消乐（本地记录最快通关和最常消除的人） |

加粗的是今年新做的。

**这份清单的意义**：下面所有方向都不与它们重复。凡是 nofan、PREFiX 有而我们「其实已经有了」的（多账号切换、看上下文、剪贴板发图、通知），我不会再列进来当新方向。

## 一、「我的饭否是我的」——数据类方向

这一组是整个调研里最大的一块空白，也是我最想推的方向。

理由很朴素：饭否已经十几年了，用它的人都是老用户，数据只存在饭否服务器上，没有任何官方导出。GitHub 上围绕饭否的开源项目里，**做备份/导出的有四个，做客户端的只有两个** —— 说明这个需求真实存在，而且一直没被好好满足。

而我们有一个别人没有的优势：**用户已经在浏览器里登录了**。那四个备份项目全都卡在同一个地方——要用户自己去申请 API 密钥、配置 GitHub Actions、管理 secrets。我们不用，一键授权就完事。

### 1.1 个人年度报告

**是什么**：设置页点一个按钮 → 进度条同步你今年发的饭 → 新标签页打开一张排版好看的报告：今年发了多少条、多少字、几点最活跃、连续发言最长多少天、高频词是什么、跟谁互动最多、被谁 @ 最多。做成适合直接截图发出去的样子。

**灵感来源**：
- [`j178/fanfou-cli`](https://github.com/j178/fanfou-cli) 有个 `fan --dump` 命令，把全部消息存成 JSON。它证明了「我想要我的全部数据」是个老需求（这项目 2017 年的）。
- 年度报告的形式是网易云/Spotify 那一套，饭否没人做过。

**我们离它多远**：设计已经全部定完，在 `docs/spec-annual-report.md`。技术前提全部验证过了——OAuth 通道能用、需要的三个 API 接口都确认过分页参数、存储方案也算过账（一万条消息约 1MB，安全）。**可以直接开工**。

**代价**：P0（能出报告）约 1.5~2 天，P1（关键词榜+互动榜+被@统计）再 1 天。

**限制，你得知道**：
- 饭否 API 不返回「你什么时候收藏的」，只有「被收藏的消息是什么时候发的」。所以收藏统计的口径只能是「你现在的收藏里，发表于今年的有多少条」，报告里会写明。
- 「被 @ 次数」可能翻不到底（API 分页有深度上限），翻不到就标「至少 N 次」，不编数字。

### 1.2 完整备份与导出

**是什么**：把你自己发过的全部消息、收藏、图片链接存到本地，能导出成 JSON（给程序读）和 Markdown（给人读）。换电脑、换浏览器、哪天饭否有个三长两短，你手里有一份。

**灵感来源**：
- [`LitoMore/fanfou-export`](https://github.com/LitoMore/fanfou-export)：承诺只有一句「导出你的全部饭否消息」。窄，但清楚。
- [`kingcos/fanfou_backup`](https://github.com/kingcos/fanfou_backup)：今年还在更新（2026-06），用 GitHub Actions 定时备份消息 JSON + 图片。**证明这需求今天还活着**，但它要求用户会配 GitHub secrets。
- [`Allianzcortex/FF-Backup`](https://github.com/Allianzcortex/FF-Backup)：2018 年就有人做，43 星，但登录/授权那关劝退了很多人。

**我们离它多远**：比想象的近。`feature/personal-archive` 这条分支上已经躺着一份写了一半的实现——消息规范化、去重合并、关键词统计、互动排行、收藏导出 Markdown、导出打包，这些逻辑都写完了还带单元测试，只差同步器和界面。这个分支从 7 月 6 号起就没动过，**没合并进主线**。

**代价**：如果跟年度报告一起做，多花 1~2 天；单独做要重写同步器，不划算。

**这里有个需要你拍板的事**（详见第六节）：年度报告的设计是「不存消息原文，只存统计用的轻量记录」，备份的设计是「存全文」。两者的存储方案冲突，得选一个。

### 1.3 收藏导出成 Markdown

**是什么**：把你的收藏导出成一个 Markdown 文件，按月分组，每条带原文、作者、时间和回到饭否的链接。可以直接丢进 Obsidian 或者任何笔记软件。

**灵感来源**：同 1.2 的 `fanfou-export`。另外 [`riophae/PREFiX`](https://github.com/riophae/PREFiX)（一个老 Chrome 饭否客户端）当年就做了收藏视图，说明「收藏」对饭否用户是个重要的东西，不只是随手点点。

**我们离它多远**：格式已经设计好，分支上的代码里连生成 Markdown 的函数都写完了。

**代价**：约 0.5~1 天，是备份功能做完之后顺手能切出来的一块。

### 1.4 图片一起备份下来

**是什么**：备份的时候把你发过的图、收藏里的图，真的下载到本地文件夹，而不是只存个链接（链接哪天失效了就什么都没了）。

**灵感来源**：`kingcos/fanfou_backup` 就是 JSON + 图片一起备份的。

**我们离它多远**：分支上有个下载图片的后台文件，但没接通。

**代价**：约 1 天。**需要给插件加一个「下载」权限** —— 这会让 Chrome 在安装时多显示一条权限提示，也会让将来上架审核时多一项需要解释的东西。所以这个方向我建议放最后，等前面几个都稳了再说。

## 二、日常顺手的小功能

不改变什么，但每天都用得上。

### 2.1 一键撤回刚发的消息

**是什么**：发完消息，右下角出现一个小提示条「消息已发送 · 撤回 (30s)」，倒计时 30 秒。手滑发错、错别字、发错账号，点一下就没了。30 秒后提示条自己消失。

**灵感来源**：nofan 的 `nofan undo` 命令，一句话说明是「Delete last status」（删掉刚发的那条）。命令行工具都觉得这功能值得做，网页上更该有——网页上现在要撤回，得找到那条消息、鼠标悬停出删除键、点击、确认，四步。

**我们离它多远**：设计定完了，在 `docs/spec-undo-status.md`。删除的技术链路是现成的（批量删消息功能里已经跑通了，走的是网页会话，不需要额外授权）。整个改动就三个新文件加一行改动。

**代价**：约 0.5 天。**这是整个清单里性价比最高的一项，而且不依赖任何其他决定。**

**取舍**：30 秒内连发两条，只有最后一条能一键撤回（不做队列，界面会变复杂）。

### 2.2 热门话题面板

**是什么**：侧栏加一块「现在大家在聊什么」，显示饭否当前的热门话题，点进去看。

**灵感来源**：nofan 有 `nofan trends` 命令，专门拉话题趋势时间线。我们现在有的是 `check-saved-searches`——**你关注的话题有没有新消息**，方向是反的：那个是「盯着我关心的」，这个是「看看大家在聊的」。两者不重复。

**我们离它多远**：新想法，还没做过设计。需要先确认饭否的话题接口现在还通不通（nofan 里有，但得实测）。

**代价**：估计 0.5~1 天，前提是接口可用。这项**风险在饭否那边**，不在我们这边。

### 2.3 搜索结果页增强

**是什么**：饭否自带搜索，但搜索结果页很朴素。可以把时间线上已有的增强（展开上下文、图片处理、静音过滤）也应用到搜索结果页。

**灵感来源**：nofan 的 `nofan search`、PREFiX 的搜索面板。两个不同形态的客户端都专门做了搜索，说明用户是真的会去搜自己或别人说过的话。

**我们离它多远**：新想法。好处是它主要是「把现有功能的作用范围扩大」，不是从零造。

**代价**：估计 0.5 天，但得先看饭否搜索结果页的 HTML 结构跟时间线像不像，不像的话会翻倍。

## 三、好看一点

### 3.1 界面美化（已在计划里但没动）

**是什么**：不改布局，只做「非破坏性」的视觉升级——统一配色、字重和字号的层次、把生硬的边框换成很淡的阴影、输入框加现代一点的聚焦效果、hover 加平滑过渡。

**灵感来源**：这个不是来自兄弟项目，是之前自己踩坑踩出来的结论。之前试过激进方案（大卡片、毛玻璃、Bento 网格），结果把设置页和侧栏本来就密的信息挤爆了，输入框被压扁、文字重叠——**属于负优化**。所以策略改成「只改感觉，不改结构」。

**我们离它多远**：五步计划写在 `tasks/todo.md` 里，工作树也建好了（`feat/beautify-plan`），但**一行代码都还没写**。

**代价**：五步大概 2~3 天，但可以拆开做，第一步（颜色变量池）做完就能看到效果。

### 3.2 自定义配色

**是什么**：让用户自己选插件相关界面的主色调。

**灵感来源**：nofan 有个 `nofan colors` 命令，专门让用户自定义命令行里的配色方案，还配了动图教程。**一个命令行工具都专门给配色做了交互式界面**，这说明饭否用户群体里「想让它像我的」这个诉求挺强的——头像壁纸功能受欢迎大概也是同一个原因。

**我们离它多远**：新想法。技术上不难（CSS 变量），但应该等 3.1 的颜色变量池做完再做，否则等于白干一遍。

**代价**：3.1 做完之后约 0.5 天。

## 四、给愿意折腾的人

### 4.1 API 调试面板

**是什么**：设置页加一个开发者面板，能直接对饭否 API 发任意的 GET/POST 请求看返回结果。用你已经授权的身份，不用另外配密钥。

**灵感来源**：nofan 有 `nofan get <uri>` 和 `nofan post <uri>` 两个命令，让用户直接发自定义请求。它敢做这个，是因为用命令行的人本来就是折腾型的。

**我们离它多远**：新想法。技术上最简单的一个——授权通道已经通了，本质上就是加个输入框和一个显示结果的区域。

**代价**：约 0.5 天。

**但我得说实话**：这是整个清单里**受众最小**的一项。装浏览器插件的饭否用户里，想手发 API 请求的可能不到 1%。它的真正价值是给我们自己开发新功能时当试验台用，不是给用户的。要做的话建议默认隐藏。

## 五、明确不做的（反向灵感）

这一节也是调研的产出，而且可能比上面任何一条都值钱——**知道不做什么，比多做几个功能重要**。

### 5.1 不在插件里重做一个完整客户端

[`riophae/PREFiX`](https://github.com/riophae/PREFiX) 是个老 Chrome 饭否客户端，做过收藏视图、搜索、通知、未读数、缓存控制、图片上传、时间线位置记忆——功能很全，50 星，**2020 年 6 月之后就没再更新了**。

[`mcxiaoke/fanfouapp-opensource`](https://github.com/mcxiaoke/fanfouapp-opensource) 是安卓客户端，450 星，是这个生态里最受欢迎的开源项目，**2016 年停更**。

这两个项目的共同点：都是「完整客户端」，都很好，都死了。做一个完整客户端要持续跟着网站变，一个人维护不下去。

**我们的定位应该是「增强现有网页」，不是「替代它」**。网页由饭否维护，我们只贴补丁——网站改版了我们修补丁，而不是整个重写。这也是为什么上面所有方向里，没有一条是「在插件里看时间线」。

### 5.2 不做云端、不做服务器、不做 AI

- 不做云同步：一旦有服务器就有成本、有隐私责任、有跑路风险。所有数据留在你自己浏览器里。
- 关键词提取不用 AI、不联网：用本地的确定性算法，结果可复现，也不用担心你的消息被发到哪个大模型那儿去。年度报告页脚会写明「由太空饭否在你的浏览器本地生成，数据不上传任何服务器」。

## 六、有一件事需要你拍板

不是功能，是个岔路口，卡着第一组（数据类）所有方向。

我们有两份设计文档，对同一批数据给了**相反**的存储方案：

| | 备份方案（6 月 8 日写的） | 年度报告方案（7 月 12 日写的） |
| --- | --- | --- |
| 存什么 | 消息全文，能原样导出 | 只存统计用的数字，**原文用完就扔** |
| 为什么 | 为了「我的数据我留着」 | 为了「省空间，一万条只占 1MB」 |
| 收藏 | 导出成 Markdown + 图片 | 只数个数 |

而那条没合并的分支上，写了一半的代码走的是**备份方案**（存全文），但年度报告要的统计逻辑它也全写好了。

三条路：

1. **合并成一件事**：把分支上写好的代码捞回来，存储改成轻量方案，导出功能保留。省半天多，但要改数据结构。
2. **拆成两个功能**：「年度报告」和「个人备份」各做各的，共用同一个同步器。功能最完整，工作量翻倍。
3. **只做年度报告**：分支废弃，按 7 月的方案从头写。最快出东西，但「备份」这个需求就丢了——而它恰恰是整个调研得出的第一结论。

**我的建议是第 1 条。** 理由：在用户心里「留下我的饭否」和「看看我今年发了啥」本来就是一件事，拆成两个功能会让设置页变复杂；而且分支上那些代码和测试是现成的，捞回来比重写划算。

## 七、一页看完

| 方向 | 现在什么状态 | 粗估工作量 | 灵感来源 |
| --- | --- | ---: | --- |
| 一键撤回 | 设计定稿，可开工 | 0.5 天 | nofan `undo` |
| 年度报告 | 设计定稿，可开工 | 2.5~3 天 | fanfou-cli `--dump` |
| 完整备份导出 | 分支上有半成品，未合并 | +1~2 天 | fanfou-export / FF-Backup / fanfou_backup |
| 收藏导出 Markdown | 代码写好了，没接通 | 0.5~1 天 | fanfou-export / PREFiX |
| 图片一起备份 | 有个空壳文件 | 1 天，**要加权限** | fanfou_backup |
| 热门话题面板 | 新想法 | 0.5~1 天 | nofan `trends` |
| 搜索结果页增强 | 新想法 | 0.5~1 天 | nofan `search` / PREFiX |
| 界面美化 | 计划写好，没动手 | 2~3 天，可拆 | 自己踩坑的结论 |
| 自定义配色 | 新想法 | 美化之后 0.5 天 | nofan `colors` |
| API 调试面板 | 新想法 | 0.5 天 | nofan `get`/`post` |

**如果让我排**：先做一键撤回（半天见效，不依赖任何决定）→ 你拍板第六节的岔路 → 年度报告 P0 → 备份导出 → 剩下的看你心情。

界面美化可以随时插进来，它跟上面所有功能都不冲突。

## 八、另外，还有一件跟功能无关的事

**插件现在怎么装、将来能不能装。**

原来的 Chrome 商店条目因为 Manifest 没及时更新，已经被下架了；而且接受 Manifest V3 改造的那位仓库维护者不是饭否官方，也不掌握那个条目。所以现在只能开发者模式加载文件夹。

要不要自己重新上架商店，写在 `docs/distribution-decision-guide.md` 里了（那份也是写给你一个人读的，包含费用、流程、哪些必须你本人做）。

**这里只提一件跟上面方向有关的**：如果哪天要上架，有个东西必须先删——插件在正式构建里会加载一段谷歌统计代码，商店明确禁止加载远程代码。而且那段代码用的是 Universal Analytics 旧版本，谷歌 2023 年就停止处理它的数据了，**也就是说它现在既挡着上架、又收不到任何数据**。直接删掉就行，不用找替代品。这是分发路线上最省力的一步。
