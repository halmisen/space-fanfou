## 2. 最近已落地的核心进展

### 2.1 分支同步与模式入口校正

- 已确认 `src/features/avatar-wallpaper/metadata.js` 中存在 `match3Mode` 入口，即设置里的“羊了个羊模式（实验）”。
- 已将传统中置布局收敛为羊模式的唯一实现，不再保留旧的双侧分布式布局入口。
- 已将 `2026.2` 的最新主线能力并入当前分支，避免继续在过时实现上修补。

### 2.2 羊了个羊模式的最新视觉/规则表达

- 点击牌、槽位牌、飞行动画牌都已统一成“麻将牌矩形底 + 头像贴片”的牌面，而不是圆头像。
- 配对线索已改成只看“相同头像”，移除了数字徽章和按类型着色的提示，规则表达更接近原版。
- 被遮挡牌现在使用独立遮挡层表达，不再依赖头像本身是不是偏灰；这解决了“灰头像看起来像不能点、但其实能点”的误判问题。
- 底部托盘状态已拆成两个信息块，分别显示“剩余牌”与“槽位”，避免把关键状态藏在一行小字里。
- 羊模式现在固定使用传统中置布局，支持中心主牌阵、独立牌堆、侧边牌堆与盲盒牌堆的组合布局。
- 传统布局现在会按视口自动缩小牌面以避免小屏裁切，并补上单独的“重开”入口，减少失败/通关后的死路感。
- 传统布局的最小化状态现在会在同标签页页面切换后保持，不会一进新页面就重新全屏展开。
- 传统布局中心主牌阵已从系统字体采样切到固定“饭否”字模，并改成“顶层牌负责写字、下层只做支撑”的分层策略。
- 托盘失败判定已收紧到 `7/7` 满槽即结束，并补上居中的“游戏结束”状态特效。

## 5. 当前风险与待确认点

- 羊了个羊模式的“可点 / 不可点”表达已经比前几轮清楚，但最终体感仍需要真实页面人工确认，尤其是头像内容复杂、颜色偏灰时的识别性。
- 传统中置布局虽然已落地，但桌面端和窄屏端的真实可读性、误触率、HUD 压迫感仍需要人工验收，尤其是固定“饭否”字模是否足够像、是否仍需再收字距。
- 当前传统布局已经是羊模式主路线，但仍是“更像原作”的近似重建，不是原版逐关脚本；如果后续还要继续拟真，关卡节奏与按钮文案仍有调整空间。
- 由于本轮还未做人工验收，是否继续增强遮挡强度、层级阴影、托盘节奏反馈和移动端按钮密度，建议根据真实页面体验再定。

## 6. 晚点继续时建议从这里开始

如果晚点要继续这条线，建议先从下面这组检查开始：

1. 在真实 Chrome / 饭否页面打开“羊了个羊模式（实验）”，确认灰头像、浅色头像、黑白头像三类牌是否都能一眼分辨“可点/不可点”。
2. 打开“羊了个羊模式（实验）”，分别在桌面宽度和窄屏宽度下确认固定传统棋盘不会被裁切，且“重开 / 最小化 / 恢复棋盘”三个入口都可顺畅使用。
3. 在真实页面里直观看一眼中心牌阵是否已经能读出“饭否”，如果还不像，优先继续收字模本身而不是再回到字体采样方案。
4. 检查底部“剩余牌 / 槽位”信息是否足够醒目，是否还需要更接近原作的节奏反馈。
5. 再决定下一步是继续做“状态可读性增强”，还是继续微调传统牌阵的字距、层级和移动端 HUD。
