# Spec：玻璃首页（Glass Home）—— iOS 26 毛玻璃风格的 /home 重做模式

- 日期：2026-07-10
- 状态：草案，待用户确认设计方向
- executor: claude-fable-5 / run_id: glass-home-spec-v1

## 一、这是什么（Building）

给太空饭否插件新增一个**默认关闭**的功能模块「玻璃首页」。用户在设置里打开后，访问 `fanfou.com/home` 时不再显示饭否原版页面，而是显示一个我们完全自己设计的首页界面——iOS 26 Liquid Glass（毛玻璃）设计语言，数据通过插件已有的 OAuth API 通道从饭否服务器获取。

原理：门面换成我们的，后厨还是饭否的。不需要任何自建服务器。

## 二、明确不做（Not Building）

- **不改动任何现有功能模块**。老用户不打开开关，一切照旧。
- **不接管 /home 以外的页面**（个人主页、私信、随便看看等），点击链接跳回原版页面。
- v1 阶段**不做发言、回复、转发、收藏等写操作**，只做"看"。
- 不做"编辑已发消息""发视频"等饭否服务器本身不支持的能力。
- 不重写现有 30+ 模块去适配新首页——新首页自带所需功能，两边互不干扰。

## 三、分阶段计划

2. 每张图旁边可选写一行"喜欢它的哪一点"（写在同目录 `notes.md`，没有也行）。

不阻塞 Phase 1，参考图到位后用于校准视觉方向。

### Phase 1：静态原型（不碰插件代码，纯看效果）

用一个独立 HTML 文件做出新首页的完整视觉稿：假数据（虚构的时间线消息、头像、图片），真设计（完整 Liquid Glass 语言）。通过 Artifact 发布成网页链接，用户在浏览器里直接看、直接提意见，改起来是分钟级的。

- 产出物：`docs/design-refs/glass-home/prototype.html`（源文件）+ Artifact 预览链接
- 使用 `/design` 技能产出，参考 Phase 0 的图
- 迭代到用户说"就是这个感觉"为止，**视觉不满意绝不进入 Phase 2**

### Phase 2：接入真实数据的只读时间线（第一次碰插件代码）

新建功能模块 `src/features/glass-home/`：

| 文件 | 作用 |
|---|---|
| `metadata.js` | 定义开关，`defaultValue: false`，标签"玻璃首页（实验性）：用全新设计取代饭否首页" |
| `glass-home@content.js` + `.less` | 开关开启时尽早隐藏原版页面内容，防止旧页面闪现 |
| `glass-home@page.js` + `.less` | 挂载新界面，调 API 拉时间线并渲染 |

技术要点（已在现有代码中验证可行）：

- 内容脚本在 `document_start` 运行（`static/manifest.json:22`），有能力在原页面绘制前动手。
- 数据通道复用现有 OAuth 模块，调用方式与互相关注功能相同（`src/features/check-friendship/@page.js:94` 的 `fanfouOAuth.request(...)`），v1 主要用 `statuses/home_timeline.json`。
- 模块用 `applyWhen` 限定只在首页生效（参考 `@libs/pageDetect` 已有的页面判断函数）。
- UI 用 Preact 渲染（项目设置页已在用，无新依赖）。
- 界面右上角常驻「回到原版」按钮：点击即关闭本功能开关并刷新页面。

v1 功能清单（只读）：

1. 展示登录用户的首页时间线：头像、昵称、消息正文、图片缩略图、相对时间、来源
2. 下拉到底自动加载更早的消息（API 翻页）
3. 点击头像/昵称 → 跳原版个人主页；点击图片 → 查看大图
4. 未授权 OAuth 时显示引导卡片："请先在设置页完成饭否授权"
5. 「回到原版」按钮

## 四、设计语言：iOS 26 Liquid Glass 基调（Phase 1 起点，可被参考图修正）

- **层次**：壁纸层（用户头像墙或渐变）→ 内容玻璃卡片层 → 悬浮控件层（顶栏/操作条）
- **玻璃质感**：半透明表面 + 强背景模糊（`backdrop-filter: blur(20px+)` + `saturate`），边缘 1px 高光描边模拟折射
- **形状**：大圆角（卡片 20–28px），控件胶囊形
- **明暗**：浅色/深色两套，跟随系统
- **动效**：克制——卡片入场淡入上浮、按钮按压缩放，不做长动画
- **字体**：默认跟随系统中文字体栈；与现有「饭否字体预设」功能的关系在 Phase 2 实现时确认（预期：玻璃首页内部自成体系，不受其影响）

## 五、关键决策与理由

1. **先原型后插件**：用户没有开发经验，视觉迭代放在最便宜的地方（单个 HTML 文件）进行，插件工程只承接已定稿的设计。
2. **默认关闭 + 独立模块**：最坏情况 = 多一个没人开的彩蛋；对未开启用户零性能影响（羊了个羊已验证此模式）。
3. **只读起步**：写操作（发言/回复）涉及错误处理和防重复提交，风险高一个量级，放到界面被验证受欢迎之后。
4. **数据走 API 而非抓取原页面**：设计自由度 100%，且不依赖饭否 HTML 结构。

## 六、最脆弱的假设（Premise Collapse）

**本计划假设 `statuses/home_timeline.json` 返回的数据足以还原首页时间线的全部内容（含图片、转发、回复上下文）。**若某类内容 API 缺字段（比如某些历史消息的图片格式），对应卡片会显示不完整。缓解：Phase 2 第一步就是用真实账号拉一页数据核对字段完整性，发现缺口先降级显示（点击跳原版），不阻塞主流程。

已知非风险：饭否官网多年不更新，接管后不存在"对方改版搞崩我们"的问题；OAuth 通道、document_start 时机均已在现有功能中验证。
